# LCC 测试执行检查表与结果状态规范

| 属性 | 内容 |
|---|---|
| 文档编号 | LCC-EXEC-001 |
| 版本 | V1.0-DRAFT |
| 适用项目 | HighwayEnv LCC 学习型测试 |

## 1. 执行前检查表

- [ ] 当前 Conda 环境为 `adas-test`。
- [ ] Python、HighwayEnv、Gymnasium、NumPy、pytest 版本已记录。
- [ ] 被测控制器版本和参数已冻结。
- [ ] 测试用例版本和判据版本已确认。
- [ ] 随机种子、初始横向偏差、初始速度、噪声和步数已确认。
- [ ] 当前场景的实际车道类型已检查（StraightLane / SineLane）。
- [ ] 环境观测字段、动作空间与测量接口正常。
- [ ] 输出目录可写，不会覆盖历史基线。
- [ ] 测试脚本、评测代码可以启动。
- [ ] 对有验收阈值的用例，阈值已在执行前确定；没有阈值的用例标记为 CHARACTERIZATION。

## 2. 执行中检查表

- [ ] 记录 run_id、用例 ID、版本、配置和开始时间。
- [ ] 检查实际执行步数和终止原因。
- [ ] 检查数据是否缺失、重复、NaN 或 Inf。
- [ ] 检查控制输出是否符合动作接口范围。
- [ ] 保存每步状态和诊断日志。
- [ ] 发生环境/采集问题时暂停或标记 INVALID/BLOCKED，不混记为功能 FAIL。
- [ ] 对异常结果保留原始数据，不覆盖已有运行结果。

## 3. 执行后检查表

- [ ] 运行结果有最终状态。
- [ ] 计算的指标能够从原始 CSV 重算。
- [ ] 失败场景能用相同配置重现，或记录不可复现情况。
- [ ] FAIL 项已生成缺陷记录或遗留风险记录。
- [ ] 回归结果关联原缺陷与修复版本。
- [ ] 报告区分 PASS、FAIL、BLOCKED、INVALID、NOT RUN、CHARACTERIZATION。
- [ ] 原始日志、配置、图表和报告已归档。

## 4. 状态定义

| 状态 | 含义 | 是否计入 PASS/FAIL 统计 |
|---|---|---|
| PASS | 执行有效，全部已冻结判据满足 | 是，计入 PASS |
| FAIL | 执行有效，至少一项已冻结判据不满足 | 是，计入 FAIL |
| BLOCKED | 前置条件、环境、资源或依赖缺失，无法执行 | 否，单独统计 |
| INVALID | 已执行但环境、步骤或数据缺陷导致结果无效 | 否，单独统计 |
| NOT RUN | 尚未执行 | 否，单独统计 |
| CHARACTERIZATION | 采集性能特性，但尚无批准的二元验收判据 | 不进入 PASS/FAIL 统计 |

## 5. 缺陷记录最小字段

- 缺陷 ID、标题、发现阶段、严重度/优先级（仅按学习项目约定）；
- 关联需求 ID、测试用例 ID、run_id；
- SUT 版本、环境配置、随机种子、场景和初始化参数；
- 前置条件、复现步骤、预期结果、实际结果、复现率；
- 日志、曲线、CSV 等证据路径；
- 已确认事实、根因假设、待验证事项；
- 责任角色、处理状态、修复版本、回归结果、关闭依据。

## 6. 测试报告最小目录

1. 摘要与测试结论。
2. 测试目标、范围及不在范围内的内容。
3. SUT 版本、配置、环境和工具版本。
4. 需求/场景覆盖情况。
5. 执行统计（PASS/FAIL/BLOCKED/INVALID/NOT RUN/CHARACTERIZATION）。
6. 指标结果与代表性曲线。
7. 缺陷及回归状态。
8. 测试限制、风险和未覆盖项。
9. 结论、遗留问题和下一步建议。
10. 附录：用例清单、日志索引、配置和版本记录。
